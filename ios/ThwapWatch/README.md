# Thwap for Apple Watch (scaffold)

A standalone watchOS app plus a WidgetKit complication. It runs against stub data for now. Networking and sign-in come from the watch design doc.

## Why a sibling project

The watch app lives in its own project, `ios/ThwapWatch/ThwapWatch.xcodeproj`. It is not a new target inside `ios/App/App.xcodeproj`. The Capacitor project is regenerated by `npx cap sync` and `pod install`, so a hand-added target there could be lost or broken by tooling we don't control. Keeping it separate leaves the iOS App target and its build settings exactly as they were. The watch app is standalone (`WKApplication`, `WKRunsIndependentlyOfCompanionApp = YES`), so it doesn't need to be embedded in the phone app to run.

The project is generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`. Edit the yml and regenerate the project, don't edit the pbxproj by hand:

```sh
brew install xcodegen   # once
cd ios/ThwapWatch && xcodegen generate
```

## Layout

| Path | What |
|---|---|
| `ThwapCore/` | Swift package with the pure logic: models that mirror the real JSON (`/api/done`, `/api/login?action=session`), the `ThwapAPI` protocol, `StubThwapAPI` fixtures, `CheckOffQueue`, `RingMath`, `DrillTimer`, `RingStore` (App Group). No UI. |
| `WatchApp/` | SwiftUI screens: Today, drill running, THWAP stamp, Game Day Goals. Plus `Haptics`. |
| `Complication/` | WidgetKit complication: circular (3 concentric rings) and rectangular. |
| `Shared/` | Theme tokens and the ring view, compiled into both the app and the complication. |

Bundle ids: `com.thwaphockey.app.watchkitapp` (app), `.watchkitapp.complication`, `.watchkitapp.tests`. App Group: `group.com.thwaphockey.app`. The App Group needs registering on the Apple Developer account before a device build will sign.

## Content source

Drill names, cues and timings come from `index.html` (`DRILLS`, `SHOOT_DAYS` day 1, `WORKOUTS` w1wed, `THWAP_DRILL_SCRIPT`). Work seconds are reps x perRep x sides, or shots x everySeconds for callout drills, or rounds x restSeconds x sides for rounds drills. Game goals come from `hockey_game_goals.html` and the game from `lib/schedule_store.js`. The player is a placeholder ("Demo"), not a roster kid.

## Haptics

| Moment | `WKHapticType` |
|---|---|
| Timer starts | `.start` |
| Any set ends | `.notification` (strongest, felt mid-rep) |
| Check-off stamp | `.success` (reads as "got it", kept for the stamp only) |

The simulator plays no haptics. Judge these on a real watch.

## Build and test

```sh
cd ios/ThwapWatch
xcodebuild -project ThwapWatch.xcodeproj -scheme ThwapWatch \
  -destination 'platform=watchOS Simulator,name=Apple Watch Series 11 (46mm)' test
# logic only, on the Mac:
cd ThwapCore && swift test
```

Launch arguments put any screen on glass for screenshots: `-thwapScreen today|run|stamp|goals`, `-thwapGameDay`, `-thwapElapsed <seconds>`.

## Swapping in the real client

Implement `ThwapAPI` against the real endpoints and replace `StubThwapAPI(...)` in `WatchApp/ThwapWatchApp.swift`. `CheckOffQueue` is in memory for now. Persist `pending` (it's `Codable`) when the real client lands so an offline check-off survives a relaunch.
